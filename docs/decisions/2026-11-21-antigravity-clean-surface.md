# Antigravity как четвёртый источник: только чистый диалог, один файл на беседу

## Контекст

Сессии Google Antigravity (десктопное приложение и CLI `agy`) лежат в
`~/.gemini/antigravity*/brain/<id>/.system_generated/logs/` как JSONL из шагов
(`step_index`, `source`, `type`). Их нужно было добавить в общий индекс рядом
с Claude Code, Codex и Cursor (`source="antigravity"`), не затащив в
эмбеддинги служебный шум. Реализация пришла в PR #65; при доводке до main
ревью и прогон на живых сессиях нашли два бага.

## Решение

- В чанки идут только `USER_EXPLICIT/USER_INPUT` (с вырезанными
  `<ADDITIONAL_METADATA>`, `<USER_SETTINGS_CHANGE>`, `<SYSTEM_MESSAGE>`,
  `<EPHEMERAL_MESSAGE>`, `<CONTEXT_SUMMARY>` и обёрткой `<USER_REQUEST>`) и
  `MODEL/PLANNER_RESPONSE.content`. `thinking`, `tool_calls`, вывод тулов
  (`GENERIC`), системные сообщения и `CHECKPOINT` остаются только в сыром
  следе — для `grep`, `expand_around`, `step`.
- Субагенты отсекаются по `conversation_summaries.db` (`parent_conversation_id`,
  `agent_name`, `nesting_depth > 0`), без строки в БД — по первому
  `SYSTEM_MESSAGE` без пользовательского ввода.
- На беседу выбирается один канонический файл: `transcript_full.jsonl` важнее
  `transcript.jsonl`, дальше больший и свежий; одинаковый id в двух
  поверхностях схлопывается. Индексатор удаляет из индекса все прочие пути
  этого источника под просканированными корнями.
- Лейбл agent-сессии (Harness Link) берётся из поля `text` конверта, даже
  если JSON обрезан.
- На командный хаб Antigravity не уходит: `hub/client.local_files` шлёт
  только Claude и Codex, `hub/storage.SOURCES` других не примет.

## Почему

- Профиль 66 живых бесед: 2 902 шага вывода тулов и 1 419 шагов с
  `tool_calls` против 194 запросов и 197 видимых ответов. Без фильтра вывод
  тулов составлял бы большую часть индекса и вытеснял бы реальный диалог,
  как heartbeat-шум в решении от 08.11.
- Сжатый и полный логи обычно лежат рядом, а одна беседа может оказаться и в
  `antigravity`, и в `antigravity-cli`. `prune_deleted` удаляет только
  исчезнувшие с диска файлы, поэтому при смене канонического файла старый
  путь оставался в индексе и сессия находилась дважды. Векторы при этом не
  теряются: новый путь переиспользует их по id беседы до удаления старого.
- Длинное сообщение Harness Link приходит в лейбл только первым куском
  чанка, JSON там обрезан, и `json.loads` падал — в `recent_sessions`
  вместо задачи показывался `{"message_id":…`.
- Маскировка секретов в проекте есть только на пути в хаб (regex на клиенте и
  Doppler на сервере). Локальный индекс не маскирует ни один источник, так что
  для Antigravity главная защита — не индексировать вывод тулов и аргументы
  вызовов, где секреты встречаются чаще всего.

## Что протестировали

- Полный набор: 560 passed.
- Сценарии (`tests/test_antigravity_scenarios.py`): пустой файл, битые и
  обрезанные строки, не-dict JSON, беседа без логов; сессия на 3+ МБ с 600
  выводами тулов и ответом, который режется на подчанки; ключ API в выводе и
  аргументах тула не попадает в чанки; хаб не берёт файлы Antigravity;
  переключение `transcript.jsonl → transcript_full.jsonl → другая
  поверхность` оставляет один путь (без фикса тест падает); частичный набор
  корней не стирает другую поверхность; смешанный индекс Claude + Codex +
  Antigravity с фильтром `source`; обрезанный конверт Harness Link.
- Живой прогон во временную БД по `~/.gemini` этой машины, без хаба:
  66 канонических файлов, 3 субагента исключены, 651 чанк, 0 сессий с
  несколькими файлами, повторный прогон ничего не переиндексирует, тегов
  обёрток и вывода тулов в чанках нет.

## Отвергли

- Индексировать `transcript.jsonl` и `transcript_full.jsonl` оба и
  дедуплицировать в выдаче — двойная стоимость эмбеддингов и шум в
  `recent_sessions`.
- Индексировать аргументы `ask_question`/`send_message` как ответы
  ассистента — 4 случая на всю историю, не стоит отдельной ветки.
- Отправлять Antigravity на хаб в этом PR — нужна поддержка на сервере
  (`SOURCES`, индексатор хаба); это отдельная задача.
