# Recall: шум heartbeat и пересказов, бонус за свежесть, подчанки длинных ходов

## Контекст

Проверка «работает ли recall исправно» 08.11.2026 показала: индекс здоров
(эмбеддер Qwen, отставание 1 минута), но выдача регулярно отдаёт не ту
информацию. Девять контрольных запросов по живому индексу (40 035 чанков)
и профилирование базы дали четыре причины:

1. **Heartbeat-шум.** 9 169 чанков (23 % индекса) — `<heartbeat>`-промпт и
   ответ одной Codex-автоматизации (сборщик очереди Whytap). Промпты
   отличаются только `<current_time_iso>`, поэтому дедуп по content_hash их
   не склеивал (3 146 чанков ровно по 6 782 символа). На «что в работе по
   whytap» два верхних хита со score 0.60 — этот системный промпт.
2. **Пересказы сжатых сессий.** 728 user-чанков «This session is being
   continued…», в среднем 22,8 KB, до 70 KB. Плотность ключевых слов
   поднимает их выше источников: на «Voyage 403 Cloud Armor» хит №1 —
   пересказ, на «Codex мост» №2 — пересказ из чужого проекта.
3. **Нет понятия «свежее».** На «последний PR по session-recall» первым
   идёт PR #22 (июль), реальный последний #62 (октябрь) — пятым. На «какой
   эмбеддер» первым — meta-doc от 02.08 про встроенный эмбеддер, решение
   про Qwen от 14.09 в топ-5 не попало. 266 из 267 meta docs датированы
   августом: генератор стоит, а доки ранжируются как актуальные факты.
4. **Длинные ходы — один размытый вектор.** 2 397 чанков длиннее 2 000
   символов (p99 = 25 KB). Эмбеддер режет на 8 192 токенах, хвост невидим;
   один вектор на 20 KB — среднее по всему.

Плюс мелочи: 150 user-чанков с невырезанным `<side-sessions-event>`
(тег с атрибутами не попадал под фильтр), FTS-фоллбэк без стоп-слов и
стемминга («Гармонии» ≠ «Гармония»).

## Решение

- **Роли.** Ход, начинающийся с `<heartbeat>` (любая роль, Claude и Codex),
  индексируется под ролью `automation`: строка в `chunks` и `fts_chunks`
  есть, вектора нет (`Store.add(chunk, None)`), в `recall_search` не
  попадает никогда. Пересказ сжатой сессии — роль `summary`: эмбеддится,
  но ранжируется только при `include_summaries=true`.
- **Подчанки.** User/assistant-ход длиннее 2 000 символов режется на окна
  ≤ 2 000 с перекрытием 200 по границе абзаца/строки/предложения/слова
  (`chunking.split_text`). Подчанки делят uuid и offsets хода; в выдаче
  ход возвращается один раз — лучшей частью. Пересказы и automation не
  режутся.
- **Свежесть.** Если запрос спрашивает про текущее состояние (регэксп:
  последний/сейчас/текущий/latest/now/…) или передан `recent_first=true`,
  к score добавляется `0.2 · exp(−age / 30 дней)` только для порядка;
  `score` в ответе остаётся чистой релевантностью. `recent_first=false`
  выключает.
- **Stale.** Хит из `metadocs` старше 30 дней несёт `stale: true`.
- **FTS.** Слова короче 3 символов без цифр отбрасываются (если остаётся
  хоть что-то), каждое слово урезается до грубого стема и матчится как
  префикс `"стем"*`.
- **Харнесс.** `_HARNESS_TAGS` + `side-sessions-event`, `ci-monitor-event`;
  открывающий тег может нести атрибуты.
- Версии экстракторов Claude и Codex → 3 (Cursor без изменений, 2).

## Почему

- Heartbeat-строки оставлены, а не выброшены: регистраторская доска
  (`recent_sessions`, PR #62) должна видеть сессию автоматизации и считать
  её активность; `started_by` и `label` на них опираются. Вектор при этом
  не нужен: в них нечего искать.
- Пересказ исключён, а не понижен весом: любой коэффициент — ещё одна
  ручка без критерия, а факт в пересказе всегда дублирует ход в том же
  транскрипте. Флаг оставляет лазейку, когда исходные ходы недоступны.
- Бонус за свежесть мал по замыслу: сегодня +0.20, месяц +0.07, три месяца
  +0.01. Он разводит почти-равные хиты и не поднимает нерелевантное
  (тест `test_recency_never_lifts_an_irrelevant_hit`). Включается по
  словам запроса, а не всегда: «почему конфликтовали refresh-токены» не
  должно предпочитать вчерашнее упоминание июльскому разбору.
- Подчанки 2 000 символов: порог, под который попадают 2 397 ходов
  (≈10 000 подчанков, 15,8 M символов) — это одноразовая стоимость на
  собственном Qwen-шлюзе; остальные векторы переиспользуются по хэшу.
- `stale` — флаг, а не исключение: meta-doc «use-second-mac» от 25.10 был
  лучшим ответом на вопрос про режим хаба.

## Что протестировали

- 29 новых тестов (`tests/test_quality.py`, расширение `test_hub_http.py`):
  роли, хранение без вектора, исключение из выдачи, доска статусов без
  heartbeat-ответов, нарезка и склейка подчанков, автоопределение
  временных слов, порядок при `recent_first` true/false/auto, stale,
  `fts_match`, инфлексии в FTS, прокидка новых параметров через хаб.
- Два старых теста зашивали версию экстрактора «2» — переписаны на текущую.
- Независимое ревью Codex (`codex:rescue`), три раунда, 16 дефектов, все
  воспроизведены кодом и исправлены, на каждый добавлен тест. Раунд 1:
  апгрейд экстрактора переэмбеддил бы весь корпус (кэш векторов проверял
  версию экстрактора, а не пространство эмбеддинга); heartbeat-ответ из
  двух текстовых блоков протекал вторым блоком в выдачу; 100+ подчанков
  одного хода забивали пул кандидатов до склейки; в FTS-only режиме бонус
  за свежесть заменял релевантность (score None); дедуп по хэшу выбирал
  произвольный дубликат вместо свежего; «CI ???» терял «CI»; `turns` в
  доске статусов считал подчанки; metadocs-коллектор мог сдвинуть
  watermark мимо недоделанных кусков хода.
  Раунды 2–3 (сбор кандидатов): обрезка пула и кап кусков на ход теряли
  точное FTS-совпадение до реранка → у KNN и FTS отдельные пулы с
  отдельными капами, FTS не режется семантическим пулом, слияние — против
  оставленных KNN-id, а не против всей выборки; один ход из 350 подчанков
  забивал оба пула → пул расширяется ×3 до лимита sqlite-vec 4096;
  `candidates=2000` давал ложный degraded → пул ограничен; отпечаток
  эмбеддера ломался на `model:latest`; склейка подчанков в metadocs
  дублировала перекрытие и принимала случайные «redis»/«disk» за шов →
  `join_pieces` снимает только шов длиной ≥ 32.
- Полная сюита после правок: 539 passed.
- На живой базе (5,8 GB): KNN с фильтром по ролям 729 мс против 831 мс
  без фильтра, FTS 7 мс — новый префильтр не замедляет.

## Отвергли

- Удалять heartbeat-ходы целиком — ломает доску статусов и `started_by`.
- Понижать вес пересказов коэффициентом — ручка без критерия.
- Бонус за свежесть всегда — портит исторические вопросы «почему».
- Исключать stale meta docs — старое решение часто единственный источник «почему».
- Резать пересказы на подчанки — 728 × 23 KB новых эмбеддингов ради
  контента, который по умолчанию исключён.
- Фильтр по `started_by == automation` вместо по ходу — сессия сборщика
  начиналась с живого вопроса, классификатор смотрит только первое сообщение.

## Дополнение 2026-11-08: копии ходов из resume-сессий

**Контекст.** После выката живой запрос «Codex мост двусторонняя связь…»
отдал один и тот же ход (`6a1ebe8f…`) двумя хитами из двух session_id:
Claude при resume копирует ходы в новый файл с тем же uuid событий. В
индексе 249 таких ходов, наборы хэшей копий совпадают полностью. Хэш-дедуп
оставляет кусок A из одной копии и кусок B из другой, а склейка подчанков
по `(source, session_id, uuid)` считает их разными ходами.

**Решение.** Ход = `_turn_key`: для Claude `(source, uuid)` (uuid4 уникален
между сессиями), для остальных источников прежний ключ с session_id (Codex
несёт session_id внутри uuid; Cursor bubbleId гарантированно уникален только
внутри composer'а). Кап кусков на ход в пуле кандидатов считает различные
хэши: копия уже взятого куска не новый кусок и не съедает слот.

**Что протестировали.** Фикстура с дрейфом векторов копий (порядок
A(res) B(orig) A(orig) B(res)) — один хит; три куска в двух копиях — все три
доходят до реранкера (находка Codex); Cursor с одним bubbleId в двух
composer'ах — два хита. 543 passed.

**Отвергли.** Склеивать копии при индексации (терять provenance копии и
переиндексировать); ключ `(source, uuid)` для всех источников (риск Cursor).
